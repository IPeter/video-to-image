# 07 — Frontend

One Next.js app in `web/`, built as a standalone container and deployed once per domain as its
own Kubernetes Deployment. The deployment's environment sets
`NEXT_PUBLIC_DOMAIN_KEY` and `NEXT_PUBLIC_API_URL`. Everything else (limits, shot labels, copy)
comes from `GET /v1/domains/:key` at runtime, so the same build works for any domain.

Design is explicitly out of scope for Phase 1. The UI uses unstyled-ish shadcn/ui components and
Tailwind defaults so a design pass later replaces tokens and components without touching flow
logic.

## Why one codebase, not one app per domain

- Every domain has the exact same flow: upload → progress → results → download.
- Differences are data (copy, shot labels, image count) and theme (colors, logo, fonts).
- A theme is a CSS-variable set selected by `domainKey`; a logo is an asset keyed by domain.
- If a domain later needs a genuinely different flow, extract the shared components into
  `packages/ui` and create a second app. Do not pre-build for that.

## Routes

| Route | Purpose |
| --- | --- |
| `/` | Upload page. Drop zone, file picker, client-side pre-checks, submit |
| `/jobs/[jobId]` | Progress while processing, then results. Shareable link for the retention window |
| `/about` (optional) | Static explanation of what the tool does for this domain |

No auth, no dashboard. The job URL is the user's handle on their result.

## Pages and states

### Upload page
- Reads domain config (server component, cached) and renders `copy.uploadTitle`, `copy.uploadHint`.
- Drop zone accepts `video/*`. Before upload:
  - size ≤ `limits.maxUploadBytes` → else inline error.
  - read duration via a hidden `<video>` element's `loadedmetadata` → warn if outside
    `[minDurationSec, maxDurationSec]` (the server re-checks; this is just fast feedback).
  - show a poster frame from the same `<video>` so the user sees they picked the right file.
- Upload with `XMLHttpRequest` for `upload.onprogress`. Show a progress bar and cancel button.
- On `202`, `router.push('/jobs/' + jobId)`.
- Map every error code from `05-api.md` to a plain-language message. Never show raw server text.

### Job page — processing
- TanStack Query polls the job every 1.5 s (switch to SSE in Phase 2) with `refetchInterval`
  returning `false` once terminal.
- Step list with states: Preparing video → Understanding the video → Extracting frames →
  Picking the best shots → Packaging. Highlight the current step, show elapsed time.
- If `status === "rejected"`: show `copy.rejectedTitle`, the model's `reason`, and a
  "Try another video" button. This is a first-class outcome, not an error.
- If `status === "failed"`: generic apology + retry link. Keep the jobId visible for support.

### Job page — results
- Header: summary sentence, image count, "Download all (ZIP)" button, expiry notice.
- Grid of cards in shot-list order. Each: thumbnail, shot label badge, timestamp, one-line reason,
  download icon. Click opens a lightbox with the full-resolution image.
- "Missing shots" callout listing required shots that were not found, with a hint to re-shoot.
- Empty state when `images.length === 0`: "No suitable scenes found" + the explanation.

## Structure

```
web/
  app/
    layout.tsx               loads domain config, sets theme class from domainKey
    page.tsx                 upload
    jobs/[jobId]/page.tsx    progress + results
  components/
    upload-dropzone.tsx
    upload-progress.tsx
    job-steps.tsx
    result-grid.tsx
    result-card.tsx
    lightbox.tsx
    missing-shots.tsx
    error-message.tsx        code → copy mapping
  lib/
    api.d.ts                 GENERATED by openapi-typescript from the Go /openapi.json
    api.ts                   openapi-fetch client typed by api.d.ts
    domain.ts                reads NEXT_PUBLIC_DOMAIN_KEY, fetches public config
    theme.ts                 domainKey → CSS variable set
  styles/
    globals.css              Tailwind + CSS variables per domain
```

## Local development

- Backend: `go run ./cmd/v2i serve --embed-worker` on `:4000` (see `02-tech-stack.md`).
- `cd web && pnpm dev` starts web on `:3000` with `NEXT_PUBLIC_DOMAIN_KEY=cars` and
  `NEXT_PUBLIC_API_URL=http://localhost:4000`.
- `pnpm gen:api` regenerates `lib/api.d.ts` from the running API's `/openapi.json`. CI runs it
  against the built Go binary and fails if the committed file differs.
- To test a second domain locally, run web again on `:3001` with a different key and add
  `http://localhost:3001` to that domain's `allowedOrigins`.

## Container

`next.config.ts` sets `output: "standalone"`. `deploy/docker/Dockerfile.web` is a multi-stage
build producing a ~150 MB image running `node server.js` on `:3000`. `NEXT_PUBLIC_*` variables
are baked at build time, so **the domain key and API URL are read at runtime** instead: a tiny
`/api/config` route handler on the Next server returns them from process env, and the client
fetches it once. That keeps one image for all domains.

## Testing

- Component tests with vitest + Testing Library for the error-code mapping and result grid.
- One Playwright e2e: upload a fixture video against `v2i serve --embed-worker --analyzer=fake`
  (canned scenes) so the test is deterministic and free. Runs in CI.
